# Общая часть адаптеров (packages/adapter-kit)

Код, который нужен каждому адаптеру агента одинаково: владение сгенерированными файлами, манифест, файл хуков, сами хуки записи, начала хода и остановки, модель сырого журнала, шаблоны и тексты, общие для агентов. Пакет не называет ни одного агента: имя агента, его модели, пути его файлов и формат его настроек задаёт сам адаптер (`adapters/claude`, `adapters/codex`), а кит получает их параметрами. Зависит от ядра и хранилища, адаптеры зависят от него, CLI — только через адаптеры.

## Правила

- **Отметки и владение** (`generate/marks.ts`, `generate/file-plan.ts`). Сгенерированный файл несёт отметку `GENERATED_MARK` (в Markdown — `MARKDOWN_GENERATED_COMMENT`, в TOML и YAML — `HASH_GENERATED_COMMENT`); прежняя русская `LEGACY_GENERATED_MARK` (до 0.8.0) тоже узнаётся. `ownershipOf` решает по манифесту и отметке: `missing`, `generated`, `edited` (исправлен руками), `human`. `planSyncFiles` строит план (`SyncPlan`: добавить, обновить, удалить, конфликты, исправленные руками), `applySyncPlan` его пишет, `requireWritable` бросает `KitError`, если план упирается в чужие файлы. Перевод строк `\r\n` расхождением не считается.
- **Манифест** (`generate/manifest.ts`): `.cyberzavod/generated.json` (`schemaVersion: 1`) — хеш sha256 каждого записанного файла и запреты, которые адаптер сам дописал в настройки. Один манифест на проект: в нём файлы одного агента, потому что агент проекта один.
- **Файл хуков** (`generate/hook-config.ts`): формат `{hooks: {Событие: [{matcher?, hooks: [обработчик]}]}}` общий у Claude Code и Codex. Свои обработчики узнаются по началу команды (`npx … cyberzavod@<версия> hook …`, любая версия, а также прежний вшитый CLI) и заменяются; чужие и прочие ключи остаются. `hookCommand` собирает команду из запускающей части (её выбирает адаптер), версии, имени хука, необязательного `agentFlag` и запасного пути на любой ненулевой код (`SKIP_ON_FAILURE`, `stopFailureCommand`). `mergedHooks`, `withoutOwnHooks`, `inspectHooks` (`installed`, `missing`, `otherVersion`, `incomplete`) — чистые функции над `Settings`.
- **Отключение** (`generate/disconnect-plan.ts`): `plannedDisconnectFiles` и `applyDisconnect` — удалить нетронутые файлы и манифест, оставить исправленные руками, убрать опустевшие каталоги внутри границ адаптера, записать или удалить файл настроек. Что убрать из самих настроек, решает адаптер.
- **Тексты процесса** (`generate/workflow-text.ts`, `generate/template.ts`): таблица этапов, секции этапов, абзацы рабочих правил для `CLAUDE.md` и `developer_instructions`, подстановки шаблонов `{{generated}}`, `{{cli}}`, `{{raw}}`, `{{drafts}}`, `{{todo}}`; неизвестная подстановка — ошибка. Всё, что зависит от агента (название вызова `/feature` или `$feature`, каталог ролей), приходит параметром.
- **Хуки** (`hooks/`): общие для агентов `record` (`recordEvent(context, source)`, `source: RawEventSource` — имя агента для `capture/<агент>/raw/` и функция «нагрузка → событие»; хук ставит проект на `session_start`, забирает отметку `human-call` на промпте человека), `turn-start` (`startTurn`) и `stop` (`gateStop`), состояние между вызовами (`state.ts`), отпечаток кода (`fingerprint.ts`), проверки проекта (`checks.ts`). `HookContext` — нагрузка, каталог проекта, каталог состояния и `KitMessages`; результат — `HookOutcome`. Отказ остановки — JSON `block` с кодом 0, причины — в доках `stop-gate.ts`. Нагрузки каждого агента в события превращает сам адаптер, кит нагрузок не знает.
- **Сырой журнал** (`capture/raw-event.ts`): модель событий `RawEvent` (`session_start`, `prompt`, `question_answer`, `tool`, `subagent_start`, `subagent_stop`, `subagent_report`, `stop`; у `tool` необязательный `callId` — для агентов, чей транскрипт называет вызов по id), чтение журнала `parseRawLog`, общие помощники нагрузок (`verdictOf`, `subagentNameOf`, `withOptional`, `MAX_COMMAND_LENGTH`). Новый вид события — новая строка в `RAW_EVENT_SHAPES`, без неё не соберётся. `capture/service-messages.ts` — `isHumanPrompt`: по началу сообщения отличает слова человека от служебных (`SERVICE_MESSAGE_PREFIXES`: Claude Code и Codex).
- **Имя хука в команде** (`hook-config.ts`): форму `npx … cyberzavod@<версия> hook <имя>` знает одно место — `NPX_HANDLER_PATTERN`; `isOwnHandler`, `inspectHooks` и `hookNameOf` читают команду им.
- **Проект** (`paths.ts`): `requireProject`, `locateProject`, каталоги `capture/<агент>/…` (`captureDirectories`); нет проекта — `KitError`.
- **Команда CLI** (`cli-command.ts`): `CLI_COMMAND` (`npx cyberzavod`) для подсказок человеку и `pinnedCliCommand(harness)` (`npx cyberzavod@<версия>`) для сгенерированных текстов.
- **Сообщения** (`messages/`): `KIT_MESSAGES` на английском и русском (`KitMessages`: хук остановки — агент читает его как задачу, хук записи, ошибки генерации). Ошибка кита — `KitError` (`errors.ts`) с `LocalizedText<KitMessages>`, `message` всегда английский. Адаптер описывает её своим каталогом: его `describeError` узнаёт `KitError` и печатает по каталогу кита. `SettingsError` — диагностика формата (английская), адаптер оборачивает её в `unparsedSettings(err, файл)`.
- Новый общий кусок попадает в кит, когда он нужен второму адаптеру; то, что знает один агент, остаётся в адаптере. Кит не называет Claude, Codex, их модели, каталоги и события. Исключение — `SERVICE_MESSAGE_PREFIXES` в `capture/service-messages.ts`: это таблица начал служебных сообщений всех агентов, по строке на каждого (комментарием отмечено, чьи); `isHumanPrompt` вызывается из общего `recordEvent` и черновика, поэтому таблица одна. Новый агент добавляет сюда свои строки.
- Тесты — на временном каталоге; данные — фабриками.
