# Общая часть адаптеров (packages/adapter-kit)

Код, который нужен каждому адаптеру агента одинаково: владение сгенерированными файлами, манифест, файл хуков, шаблоны и тексты, общие для агентов. Пакет не называет ни одного агента: имя агента, его модели, пути его файлов и формат его настроек задаёт сам адаптер (`adapters/claude`, `adapters/codex`), а кит получает их параметрами. Зависит от ядра и хранилища, адаптеры зависят от него, CLI — только через адаптеры.

## Правила

- **Отметки и владение** (`generate/marks.ts`, `generate/file-plan.ts`). Сгенерированный файл несёт отметку `GENERATED_MARK` (в Markdown — `MARKDOWN_GENERATED_COMMENT`, в TOML и YAML — `HASH_GENERATED_COMMENT`); прежняя русская `LEGACY_GENERATED_MARK` (до 0.8.0) тоже узнаётся. `ownershipOf` решает по манифесту и отметке: `missing`, `generated`, `edited` (исправлен руками), `human`. `planSyncFiles` строит план (`SyncPlan`: добавить, обновить, удалить, конфликты, исправленные руками), `applySyncPlan` его пишет, `requireWritable` бросает `KitError`, если план упирается в чужие файлы. Перевод строк `\r\n` расхождением не считается.
- **Манифест** (`generate/manifest.ts`): `.cyberzavod/generated.json` (`schemaVersion: 1`) — хеш sha256 каждого записанного файла и запреты, которые адаптер сам дописал в настройки. Один манифест на проект: в нём файлы одного агента, потому что агент проекта один.
- **Файл хуков** (`generate/hook-config.ts`): формат `{hooks: {Событие: [{matcher?, hooks: [обработчик]}]}}` общий у Claude Code и Codex. Свои обработчики узнаются по началу команды (`npx … cyberzavod@<версия> hook …`, любая версия, а также прежний вшитый CLI) и заменяются; чужие и прочие ключи остаются. `hookCommand` собирает команду из запускающей части (её выбирает адаптер), версии, имени хука, необязательного `agentFlag` и запасного пути на любой ненулевой код (`SKIP_ON_FAILURE`, `stopFailureCommand`). `mergedHooks`, `withoutOwnHooks`, `inspectHooks` (`installed`, `missing`, `otherVersion`, `incomplete`) — чистые функции над `Settings`.
- **Отключение** (`generate/disconnect-plan.ts`): `plannedDisconnectFiles` и `applyDisconnect` — удалить нетронутые файлы и манифест, оставить исправленные руками, убрать опустевшие каталоги внутри границ адаптера, записать или удалить файл настроек. Что убрать из самих настроек, решает адаптер.
- **Тексты процесса** (`generate/workflow-text.ts`, `generate/template.ts`): таблица этапов, секции этапов, абзацы рабочих правил для `CLAUDE.md` и `developer_instructions`, подстановки шаблонов `{{generated}}`, `{{cli}}`, `{{raw}}`, `{{drafts}}`, `{{todo}}`; неизвестная подстановка — ошибка. Всё, что зависит от агента (название вызова `/feature` или `$feature`, каталог ролей), приходит параметром.
- **Проект** (`paths.ts`): `requireProject`, `locateProject`, каталоги `capture/<агент>/…` (`captureDirectories`); нет проекта — `KitError`.
- **Команда CLI** (`cli-command.ts`): `CLI_COMMAND` (`npx cyberzavod`) для подсказок человеку и `pinnedCliCommand(harness)` (`npx cyberzavod@<версия>`) для сгенерированных текстов.
- **Сообщения** (`messages/`): `KIT_MESSAGES` на английском и русском (`KitMessages`). Ошибка кита — `KitError` (`errors.ts`) с `LocalizedText<KitMessages>`, `message` всегда английский. Адаптер описывает её своим каталогом: его `describeError` узнаёт `KitError` и печатает по каталогу кита. `SettingsError` — диагностика формата (английская), адаптер оборачивает её в `unparsedSettings(err, файл)`.
- Новый общий кусок попадает в кит, когда он нужен второму адаптеру; то, что знает один агент, остаётся в адаптере. Кит не называет Claude, Codex, их модели, каталоги и события.
- Тесты — на временном каталоге; данные — фабриками.
