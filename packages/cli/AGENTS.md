# CLI (packages/cli)

`cyberzavod` — npm-пакет и точка входа для человека: подключает проект (`npx cyberzavod init`), держит файлы агента в согласии с harness и конфигом, пишет решения и заметки в журнал, а командой `hook` исполняет хуки агента. Сам агентов не запускает; в сеть ходит только публикация записей (`login`, `share` и соседние команды), остальное работает локально.

## Правила

- **Команды** — таблица `COMMANDS` в `cli.ts`: строка справки, описание и обработчик, который сам разбирает свои флаги `parseArgs`. Новая команда — новая строка таблицы и файл в `src/commands/`. Ожидаемая ошибка (`EXPECTED_ERRORS`: `CommandError`, ошибки генератора, конфига, журнала и записи; ошибки `parseArgs`) печатается одной строкой с кодом выхода 1; остальное — исключение.
- **Каталог проекта** — `INIT_CWD` (его ставят pnpm, npm и npx) или текущий; у `hook` — `CLAUDE_PROJECT_DIR`; команды, кроме `init`, поднимаются от него до маркера `.cyberzavod/project.json`.
- **`init`** (`commands/init.ts`) — мастер: распознавание проекта (`detect.ts`), вопросы (`wizard.ts`), конфиг, AGENTS.md, собранный CLI в `.cyberzavod/bin/cyberzavod.mjs`, строка `capture/` журнала в `.gitignore` (если журнал в проекте) и `sync`. Распознанные язык, фреймворк, менеджер пакетов и команды — подсказки и справочный `stack`, а не ограничения: человек может ответить иначе. Уже подключённый проект `init` не трогает. Рукописный `CLAUDE.md` становится `AGENTS.md`, иначе AGENTS.md пишется из `templates/rules.md`.
- **Распознавание** — таблицы маркеров (`LANGUAGE_MARKERS`, `LOCKFILES`, `FRAMEWORK_DEPENDENCIES`, `LANGUAGE_VERIFICATION`): новый язык или фреймворк — новая строка таблицы, а не условие.
- **Вопросы** идут через интерфейс `Prompter`: `terminalPrompter` для человека, `defaultsPrompter` для `--yes` и тестов. Мастер не читает stdin сам.
- **`sync`** передаёт генерацию адаптеру агента, обновляет `.cyberzavod/bin/cyberzavod.mjs` и пишет в конфиг версию harness (`HARNESS_VERSION` в `installation/installation.ts`, она же версия npm-пакета — это проверяет тест) и `stack`; `sync --check` только сообщает о расхождениях и выходит с 1 — его запускает `make check-web`.
- **Установка** (`installation/`) — harness, шаблоны и текст собранного CLI. Читает их только `assets.ts`: из исходников — с диска репозитория, а сборка (`scripts/build.ts`, esbuild) подменяет модуль встроенными текстами, и собранный файл знает себя сам. Поэтому `dist/cyberzavod.mjs` — один файл без зависимостей: его публикует npm и его же `init` кладёт в проект, где его запускают хуки. Запущенный из исходников CLI собранного себя не знает, и `init`/`sync` просят собрать его: в этом репозитории `pnpm cyberzavod` сначала собирает CLI.
- **Публикация** (`sharing/`, `commands/login.ts`, `share.ts`, `gallery.ts`) — `login`, `logout`, `share <id>`, `unshare <id>`, `gallery [--public | --private]`: вход через GitHub (device flow) и отправка записи сессии в личную галерею на сервер. Сервер принимает `GET /api/auth/github`, `GET /api/me`, `PUT` и `DELETE /api/me/recordings/{id}`, `PUT /api/me/gallery` с заголовком `Authorization: Bearer <токен>` и отвечает ошибкой `{"error", "message"}`; сервер Cyberzavod (`CyberzavodApi`, `HttpCyberzavodApi`) и GitHub (`GithubDeviceAuth`, `HttpGithubAuth`) — за интерфейсами, сеть — встроенный `fetch`, который передаётся в конструктор; все команды получают `Sharing` (`services.ts`: адрес, сервер, GitHub, хранилище токена, пауза), `createSharing` собирает настоящий, тесты подставляют заглушки из `sharing/fixtures.ts`. Адрес сервера — `CYBERZAVOD_API_URL`, по умолчанию `DEFAULT_API_URL` (`https://cyberzavod.com`). Токен — `credentials.json` (`{"token": "..."}`) в `$XDG_CONFIG_HOME/cyberzavod`, `~/.config/cyberzavod` или `%APPDATA%\cyberzavod`, права 0600 (`settings.ts`; путь — чистая функция от env и платформы); токен не печатается, не попадает в сообщения ошибок и в журнал. Запись перед отправкой читается из `sessions/` журнала проекта (тот же `requireProjectAt`) и проходит `parseRecord` ядра: сервер проверяет только конверт и размер. Ошибка сервера — `ApiError` (код и текст по-русски из ответа) и печатается как ожидаемая; `unauthorized` превращается в просьбу войти заново, `limit_reached` — в список записей с командой `unshare`. Остальные команды ничего не отправляют.
- **Выпуск** — тег `vX.Y.Z` (совпадает с `version` пакета): CI публикует пакет в npm (`.github/workflows/release.yml`).
- Пути — через `node:path`; в выводе — пути от корня проекта, а не абсолютные.
- Тесты публикации — без сети: заглушки `CyberzavodApi` и `GithubDeviceAuth`, `memoryCredentials`, а HTTP-слой — с подменённым `fetch`; ожидание входа — с мгновенной паузой `sleep`.
- Тесты — на временном каталоге и `defaultsPrompter` или заготовленном `Prompter`; вывод проверяется по перехваченному `console`.
