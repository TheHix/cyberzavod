# CLI (packages/cli)

`cyberzavod` — npm-пакет и точка входа для человека: подключает проект (`npx cyberzavod init`), держит файлы агента в согласии с harness и конфигом, пишет решения и заметки в журнал, а командой `hook` исполняет хуки агента. Сам агентов не запускает; в сеть ходит только публикация записей (`login`, `share` и соседние команды), остальное работает локально.

## Правила

- **Команды** — таблица `COMMANDS` в `cli.ts` (`Record<CommandName, Command>`): обработчик, который сам разбирает свои флаги `parseArgs`; справка команды (строка вызова и описание) лежит в каталоге сообщений. Новая команда — новое имя в `COMMAND_NAMES`, справка в `en.ts` и `ru.ts` (без неё не соберётся `tsc`), строка таблицы и файл в `src/commands/`. `runCli(argv, directory, env)` получает окружение явно, `process.env` внутри `cli.ts` не читается. Ожидаемая ошибка (`EXPECTED_ERRORS`: `CommandError`, `ApiError`, `ClaudeError`, ошибки конфига, журнала и записи; ошибки `parseArgs`) печатается одной строкой с кодом выхода 1; остальное — исключение.
- **Сообщения и язык** (`src/messages/`). Всё, что CLI говорит человеку, лежит в каталогах `en.ts` и `ru.ts` (тип `CliMessages` в `cli-messages.ts` по разделам; значение — строка или функция, при двух и более параметрах — один объект с именованными полями; `CLI_MESSAGES` в `catalog.ts`). Язык (`language.ts`): флаг `--lang <язык>` или `--lang=<язык>` в любом месте до `--`, затем `CYBERZAVOD_LANG` (неподдерживаемое значение пропускается: опечатка не должна ронять хуки), затем локаль по POSIX (первая непустая из `LC_ALL`, `LC_MESSAGES`, `LANG`; язык — часть до `_`, `.`, `@`, `-`; `C` и неподдерживаемые — английский), затем английский; неподдерживаемый `--lang` — ошибка с кодом 1 на языке без флага. Печатающая функция получает `messages: CliMessages` параметром. Ошибка для человека — `CommandError`, она хранит не строку, а `LocalizedText<CliMessages>`: `new CommandError((messages) => messages.errors.…)`; текст на нужном языке выбирает `runCli` при печати (`describe`), а `message` ошибки всегда английский. Адаптеру передаётся его набор (`CLAUDE_MESSAGES[язык]`) в `HookContext`, `DraftSessionOptions` и `PublishSessionsOptions`. Не переводятся: диагностика формата файлов (тексты `parse…` ядра, хранилища и адаптера: `RecordError`, `ProjectFileError`, `JournalError`, `DraftError` из `parseDraft` и соседи) — CLI печатает её как есть после переведённой рамки; тексты генерируемых файлов (#63) и заготовка правил `init` (`starterRules`); названия этапов из harness.
- **Каталог проекта** — `INIT_CWD` (его ставят pnpm, npm и npx) или текущий; у `hook` — `CLAUDE_PROJECT_DIR`; команды, кроме `init`, поднимаются от него до маркера `.cyberzavod/project.json`.
- **`init`** (`commands/init.ts`) — мастер: распознавание проекта (`detect.ts`), вопросы (`wizard.ts`), конфиг, AGENTS.md, собранный CLI в `.cyberzavod/bin/cyberzavod.mjs`, строка `capture/` журнала в `.gitignore` (если журнал в проекте) и `sync`. Распознанные язык, фреймворк, менеджер пакетов и команды — подсказки и справочный `stack`, а не ограничения: человек может ответить иначе. Уже подключённый проект `init` не трогает. Рукописный `CLAUDE.md` становится `AGENTS.md`, иначе AGENTS.md пишется из `templates/rules.md`.
- **Распознавание** — таблицы маркеров (`LANGUAGE_MARKERS`, `LOCKFILES`, `FRAMEWORK_DEPENDENCIES`, `LANGUAGE_VERIFICATION`): новый язык или фреймворк — новая строка таблицы, а не условие.
- **Вопросы** идут через интерфейс `Prompter`: `terminalPrompter` для человека, `defaultsPrompter` для `--yes` и тестов. Мастер не читает stdin сам.
- **`sync`** передаёт генерацию адаптеру агента, обновляет `.cyberzavod/bin/cyberzavod.mjs` и пишет в конфиг версию harness (`HARNESS_VERSION` в `installation/installation.ts`, она же версия npm-пакета — это проверяет тест) и `stack`; `sync --check` только сообщает о расхождениях и выходит с 1 — его запускает `make check-web`.
- **Установка** (`installation/`) — harness, шаблоны и текст собранного CLI. Читает их только `assets.ts`: из исходников — с диска репозитория, а сборка (`scripts/build.ts`, esbuild) подменяет модуль встроенными текстами, и собранный файл знает себя сам. Поэтому `dist/cyberzavod.mjs` — один файл без зависимостей: его публикует npm и его же `init` кладёт в проект, где его запускают хуки. Запущенный из исходников CLI собранного себя не знает, и `init`/`sync` просят собрать его: в этом репозитории `pnpm cyberzavod` сначала собирает CLI.
- **Публикация** (`sharing/`, `commands/login.ts`, `share.ts`, `gallery.ts`) — `login`, `logout`, `share <id>`, `unshare <id>`, `gallery [--public | --private]`: вход через GitHub (device flow) и отправка записи сессии в личную галерею на сервер. Сервер принимает `GET /api/auth/github`, `GET /api/me`, `PUT` и `DELETE /api/me/recordings/{id}`, `PUT /api/me/gallery` с заголовком `Authorization: Bearer <токен>` и отвечает ошибкой `{"error", "message"}`; сервер Cyberzavod (`CyberzavodApi`, `HttpCyberzavodApi`) и GitHub (`GithubDeviceAuth`, `HttpGithubAuth`) — за интерфейсами, сеть — встроенный `fetch`, который передаётся в конструктор; все команды получают `Sharing` (`services.ts`: адрес, сервер, GitHub, хранилище токена, пауза), `createSharing` собирает настоящий, тесты подставляют заглушки из `sharing/fixtures.ts`. Адрес сервера — `CYBERZAVOD_API_URL`, по умолчанию `DEFAULT_API_URL` (`https://cyberzavod.com`). Токен — `credentials.json` (`{"token": "..."}`) в `$XDG_CONFIG_HOME/cyberzavod`, `~/.config/cyberzavod` или `%APPDATA%\cyberzavod`, права 0600 (`settings.ts`; путь — чистая функция от env и платформы); токен не печатается, не попадает в сообщения ошибок и в журнал. Запись перед отправкой читается из `sessions/` журнала проекта (тот же `requireProjectAt`) и проходит `parseRecord` ядра: сервер проверяет только конверт и размер. Ошибка сервера — `ApiError` (код и текст из ответа, язык выбирает сервер) и печатается как ожидаемая; `unauthorized` превращается в просьбу войти заново, `limit_reached` — в список записей с командой `unshare`, оба с текстом из каталога сообщений. Неожиданный ответ сервера и статус без тела ошибки — `CommandError` из каталога, а не `ApiError`. Остальные команды ничего не отправляют.
- **Выпуск** — тег `vX.Y.Z` (совпадает с `version` пакета): CI публикует пакет в npm (`.github/workflows/release.yml`).
- Пути — через `node:path`; в выводе — пути от корня проекта, а не абсолютные.
- Тесты публикации — без сети: заглушки `CyberzavodApi` и `GithubDeviceAuth`, `memoryCredentials`, а HTTP-слой — с подменённым `fetch`; ожидание входа — с мгновенной паузой `sleep`.
- Тесты — на временном каталоге и `defaultsPrompter` или заготовленном `Prompter`; вывод проверяется по перехваченному `console`.
