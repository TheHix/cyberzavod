# Dev-контейнер

Изолированное окружение для разработки и для ИИ-агентов. Основано на [dev-контейнере из репозитория Claude Code](https://github.com/anthropics/claude-code/tree/main/.devcontainer).

## Запуск

**VS Code:** расширение Dev Containers → «Reopen in Container».

**Терминал** (нужен `@devcontainers/cli`):

```bash
devcontainer up --workspace-folder .
devcontainer exec --workspace-folder . zsh
```

Первый запуск ставит зависимости (`pnpm install`, `go mod download`), каждый запуск включает файрвол.

Запускайте контейнер только так — через VS Code или `devcontainer`. Файрвол включает их `postStartCommand`; если поднять `.devcontainer/compose.yaml` напрямую через `docker compose`, сеть внутри останется открытой.

Внутри:

```bash
claude                  # один раз войти в подписку; вход сохраняется в томе
make check-web check-api
make api-dev            # API из исходников на :8080, база — соседний сервис db
pnpm dev --host         # сайт на :4321
```

Порты 4321 и 8080 опубликованы на `127.0.0.1` хоста, поэтому одновременно с `make up` на хосте контейнер не запустится: остановите одно из двух.

## От чего защищает

| Риск | Как закрыт |
|---|---|
| Агент читает домашний каталог, SSH-ключи, `~/.git-credentials`, другие проекты | в контейнер смонтирована только папка проекта |
| Агент ходит куда угодно в сеть | файрвол: наружу только GitHub и домены из `ALLOWED_DOMAINS`; DNS только через резолвер Docker |
| Агент подключается к продакшен-серверу | адреса сервера нет в белом списке, ключей нет в контейнере |
| Агент получает root и снимает файрвол | от root node может только перезапустить `init-firewall.sh`, который принадлежит root |
| Ошибка при настройке файрвола оставляет сеть открытой | при любой ошибке сеть закрывается целиком; повторный запуск скрипта восстанавливает белый список |
| Агент пишет в `.git/config` или хуки команду, которую выполнит git на хосте | `.git/config` и `.git/hooks` смонтированы только на чтение |

## От чего не защищает

- **Целенаправленная утечка.** Белый список строится по IP: открыты все сервисы GitHub (любой репозиторий, gist) и общие адреса CDN. Файрвол защищает от случайного доступа, но не от агента, который намеренно выносит данные. Секретов в контейнере нет, а код и так публичный.
- **Код, который агент изменил, а вы запустили на хосте.** `Makefile`, `package.json`, скрипты, `.vscode/` лежат в общей папке. Перед запуском на хосте изменения агента нужно просмотреть: `git diff` — обычный шаг перед коммитом.

## Чего в контейнере нет — намеренно

- **Docker.** Docker-in-Docker требует привилегированного режима, а это свело бы изоляцию на нет. Проверки с Docker (`make check-docker`, `make check-scripts`) выполняет CI. Перед коммитом в контейнере достаточно `make check-web check-api`.
- **Записи в настройки git.** `git config` и `git push -u` для новой ветки делаются с хоста. Коммиты, ветки и обычный `git push` работают внутри (после `gh auth login` в контейнере).

## Файрвол

`init-firewall.sh` собирает адреса (диапазоны GitHub из `api.github.com/meta`, адреса доменов из `ALLOWED_DOMAINS`) и только потом заменяет правила. Адреса доменов резолвятся при запуске, а CDN их меняют. Если что-то из белого списка перестало открываться, перезапустите файрвол:

```bash
sudo /usr/local/bin/init-firewall.sh
```

`proxy.golang.org` отвечает с постоянно меняющихся адресов Google, поэтому новые Go-зависимости надёжнее добавлять с хоста. Уже скачанные модули лежат в томе и работают.

Добавить домен в белый список — дописать его в `ALLOWED_DOMAINS` и пересобрать контейнер.
