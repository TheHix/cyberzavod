## Как это устроено

Киберзавод — локальный harness разработки с ИИ-агентами. Он не пишет код сам и не заменяет вашего агента. Он задаёт процесс: этапы, роли, общие принципы и проверки. Из этого процесса он собирает файлы, которые понимает агент, и ведёт журнал сессий и решений. Ваш стек может меняться, и агент тоже. Процесс остаётся тем же.

Процесс по умолчанию: задача → постановка → код → ревью → проверки → фиксация. Первый агент, которого поддерживает завод, — Claude Code. Его хуки пишут журнал сессии. Из журнала собирается запись сессии: этапы, промпты, реплики станций, время и токены. Цех на сайте эту запись проигрывает.

Ничего не уходит в сеть, пока вы не попросите: с сервером говорят только команды, которые публикуют запись на сайте. Конфиг, сам инструмент и журнал лежат в вашем репозитории. Клон Киберзавода не нужен: сайт завода — лишь одна из витрин, которые умеют проигрывать журнал.

## Что нужно

- Claude Code.
- Node 22 или новее и `git`. Больше ничего: ни `jq`, ни bash, ни глобальных пакетов. Linux, macOS и Windows работают одинаково.

Сам проект может быть на любом языке и фреймворке, с любым трекером задач.

## Подключить проект: npx cyberzavod init

Из корня своего проекта:

```bash
npx cyberzavod init
```

npm нужен только здесь. `init` кладёт весь инструмент — один файл без зависимостей — в проект, в `.cyberzavod/bin/cyberzavod.mjs`. Хуки агента и все следующие команды запускают его обычным `node`. Мастер распознаёт проект: языки, фреймворки, менеджер пакетов, git и скрипты. Затем он задаёт несколько вопросов, и у каждого есть ответ по умолчанию:

- `id` проекта — латинские буквы, цифры, `-` и `_`; по нему проект называется в записях;
- процесс — `default`;
- агент каждого этапа — сейчас только Claude Code, модель `default` (её выбирает адаптер);
- команды проверок — мастер предлагает их по скриптам проекта, например `make check` или `npm run test`;
- где хранить журнал — по умолчанию в проекте, `.cyberzavod/journal`. Можно и вне репозитория, например `../<проект>.cyberzavod`.

Распознанное — подсказка, а не ограничение: на любой вопрос можно ответить иначе. `init --yes` берёт все ответы по умолчанию.

Что появляется в проекте:

- `.cyberzavod/bin/cyberzavod.mjs` — сам инструмент. Его коммитят: так хуки работают в любом клоне проекта;
- `.cyberzavod/project.json` — маркер и конфиг проекта: `projectId`, версия harness, процесс, путь журнала, агент на каждый этап (`provider`, `agent`, `model`), проверки (`verification.commands` и каталоги кода `verification.paths`) и справочный `stack`;
- `AGENTS.md` — правила проекта для агентов и людей. Если в проекте уже был рукописный `CLAUDE.md`, он становится `AGENTS.md`, иначе ложится заготовка;
- `CLAUDE.md` — тонкая точка входа для Claude Code: процесс, проверки, принципы и ссылка на `AGENTS.md`. Его генерирует завод, руками его не правят;
- `.claude/agents/` — агенты этапов `analyst`, `coder`, `reviewer`, `tester` и редактор записи `recording-editor`;
- `.claude/skills/` — скиллы `/feature` и `/publish-recording`;
- `.claude/settings.json` — хуки записи и остановки (`node .cyberzavod/bin/cyberzavod.mjs hook …`) и запрет читать и править `.env`. Ваши собственные настройки и хуки в этом файле завод не трогает;
- строка в `.gitignore` — `capture/` журнала: сырые журналы сессий в git не идут.

Уже подключённый проект `init` не трогает.

## Что сделать руками

1. Допишите `AGENTS.md`. Агенты читают его первым делом. Нужны:
   - команда форматирования (если её нет, шаг пропускается);
   - команды проверок;
   - где лежат задачи, как их читать и как ссылаться на них в коммитах;
   - правила кода и тестов: по ним пишет исполнитель, а проверяют тестировщик и ревьюер.
2. Проверьте `verification` в `.cyberzavod/project.json`. Команды идут по порядку на каждой остановке агента, который менял код в `paths` (пустой список — весь репозиторий). Пока они красные, агент не может закончить ход. Не кладите сюда то, что требует недоступной агенту среды, например Docker: это оставляют CI.
3. Закоммитьте `.cyberzavod/`, `AGENTS.md`, `CLAUDE.md`, `.claude/` и `.gitignore`.

## Когда что-то поменялось: cyberzavod sync

Файлы агента выводятся из harness завода и конфига проекта. После правки конфига выполните:

```bash
node .cyberzavod/bin/cyberzavod.mjs sync
```

Чтобы перейти на новую версию завода, выполните `npx cyberzavod@latest sync`: она перепишет и файлы агента, и `.cyberzavod/bin/cyberzavod.mjs`.

`sync` перезаписывает только файлы с отметкой «Сгенерировано `cyberzavod sync`». Если на месте такого файла лежит ваш, `sync` откажет и ничего не изменит. `sync --force` перепишет его, а `sync --check` только сообщает, что устарело; его удобно добавить в проверки проекта. `node .cyberzavod/bin/cyberzavod.mjs status` показывает конфиг, агентов этапов и сколько записей в журнале.

## Задача через цех: /feature

Откройте Claude Code в каталоге проекта и запустите:

```text
/feature <задача>
```

Задача — описание, ссылка или номер в трекере: как её читать, сказано в `AGENTS.md`. Рабочая копия должна быть чистой.

Ведущий, то есть сама сессия, код не пишет, а передаёт работу этапам. Каждый этап — агент из `.claude/agents/` со своей моделью; при `model: "default"` её выбирает адаптер:

- постановка — `analyst`, Opus: ошибка в постановке обходится дороже всего;
- код — `coder`, Sonnet, а на второй доработке Opus;
- ревью — `reviewer`, Opus;
- проверки — `tester`, Sonnet.

Ход работы:

1. Постановка. `analyst` изучает код и пишет план с критериями готовности. Ведущий показывает его целиком вместе с вопросами и ждёт вашего одобрения.
2. Код. `coder` делает задачу по плану.
3. Ревью. `reviewer` читает изменения. «На доработку» — возврат.
4. Проверки. `tester` сверяет результат с критериями и запускает проверки проекта. Дефект — возврат.
5. Фиксация. Коммиты по правилам из `AGENTS.md`. Если `AGENTS.md` описывает публикацию и выкатку, ведущий делает и их. Решения, важные надолго, записываются в журнал командой `decision`, заметки — командой `note` того же CLI.

### Возвраты

Возвраты от ревью, проверок и фиксации считаются вместе:

1. первый — `coder` на своей модели;
2. второй — `coder` на более сильной модели;
3. третий — стоп: ведущий показывает оставшиеся замечания и что уже пробовали, и зовёт вас.

### Хук остановки

Пока проверки красные и агент менял код в этом ходе, хук остановки не даёт ему закончить ход. После трёх неудачных попыток подряд он останавливается и зовёт человека. Чужие незакоммиченные правки, сделанные до хода, агента не держат.

## Журнал

Журнал — каталог из конфига (`journal`), по умолчанию `.cyberzavod/journal`. Он ваш и лежит в вашем репозитории. Каждая запись — отдельный JSON-файл:

- `sessions/` — записи сессий агента;
- `decisions/` — решения (`node .cyberzavod/bin/cyberzavod.mjs decision "<решение>" --why "<почему>"`);
- `notes/` — заметки (`node .cyberzavod/bin/cyberzavod.mjs note "<текст>"`);
- `capture/` — рабочие файлы адаптера: сырые журналы сессий и черновики записей. В них исходные тексты ваших промптов, поэтому `init` прячет `capture/` от git.

У каждой записи один и тот же конверт: версия, тип, время, проект, сессия, источник (агент или человек) и данные. Этот формат — весь договор между инструментом и витриной: свой цех для визуализации можно построить на своём журнале.

## Опубликовать запись: /publish-recording

Запустите `/publish-recording` в Claude Code в каталоге проекта. Скилл проведёт по шагам:

1. Черновик. `draft` собирает его из самого свежего сырого журнала. Черновик ложится в `capture/claude/drafts/` журнала.
2. Редактура. Сессия пишет заголовок записи и переписывает ваши промпты в чистовой вид: главное указание и уточнения. Агент `recording-editor` пишет реплики станций и мастера и вмешательства человека, то есть моменты, когда автоматика ждала вашего слова.
3. Проверка человеком. Скилл показывает таблицы промптов, реплик и вмешательств. Читайте их внимательно: в запись уйдёт то, что вы одобрите. Публикация ищет в тексте адреса и ключи, но это лишь страховка.
4. Публикация. `publish` проверяет формат и пишет `sessions/<id>.json` в журнал проекта.

Если в одной сессии шло несколько задач, каждая публикуется отдельной записью: скилл разметит их в черновике сам.

### Как запись попадёт на cyberzavod.com

Опубликованную запись CLI отправляет прямо в вашу личную галерею на сайте. Ни клон завода, ни pull request для этого не нужны.

1. Войдите через GitHub:

   ```bash
   node .cyberzavod/bin/cyberzavod.mjs login
   ```

   Команда покажет код и адрес `https://github.com/login/device`: откройте его, введите код и подтвердите. Завод просит у GitHub только публичный профиль — чтобы узнать ваш логин. Токен хранится в каталоге настроек пользователя (`~/.config/cyberzavod/credentials.json`, на Windows — `%APPDATA%\cyberzavod`), вне проекта; `logout` его удаляет.

2. Отправьте запись по её `id` — имени файла в `sessions/` журнала:

   ```bash
   node .cyberzavod/bin/cyberzavod.mjs share <id>
   ```

   Перед отправкой `share` проверяет запись так же, как сайт. В ответ он печатает ссылку вида `https://cyberzavod.com/r/?id=<slug>`: там тот же цех и журнал сборки, что у записей самого завода. Повторная отправка того же `id` заменяет запись, ссылка остаётся прежней.

3. Галерея по умолчанию закрыта: запись видят только те, у кого есть ссылка. Чтобы галерея появилась на сайте, откройте её:

   ```bash
   node .cyberzavod/bin/cyberzavod.mjs gallery --public
   ```

   Открытая галерея попадает в список [галерей](/gallery/), получает свою страницу `/gallery/?user=<login>` и входит в [аналитику](/stats/) сборок: где процесс буксует, сколько уходит токенов, когда зовут человека. `gallery --private` снова закрывает её; ссылки на записи продолжают работать.

В галерее не больше 5 записей; замена записи новой не считается. Когда лимит исчерпан, `share` покажет список ваших записей: освободите место командой `unshare <id>`. `gallery` без флагов показывает записи со ссылками, открыта ли галерея и лимит.

Для открытой галереи `gallery` печатает ещё и строку бейджа для README: бейдж «cyberzavod | N builds» ведёт в галерею. Та же строка с кнопкой «копировать» есть на странице галереи.

```markdown
[![Built at Cyberzavod](https://cyberzavod.com/api/badges/<login>.svg)](https://cyberzavod.com/gallery/?user=<login>)
```

То же можно сделать на сайте, без терминала: войдите через GitHub в меню (на телефоне — в панели «Записи») и откройте [личный кабинет](/me/). Там галерею открывают и закрывают, видят записи со ссылками, удаляют лишние и копируют строку бейджа. Загружаются записи по-прежнему только из проекта, командой `share`.

### Проект на главной сайта завода

Главная и страницы проектов сайта собираются из репозитория завода: записи — из его `.cyberzavod/journal/sessions/`, карточки проектов — из `projects/`. Чтобы ваш проект был там с карточкой, предложите pull request в [репозиторий завода](https://github.com/bysavelii/cyberzavod) с двумя файлами:

- запись `.cyberzavod/journal/sessions/<id>.json` из журнала вашего проекта;
- карточка `projects/<id>.json`: `id`, `name` и `description` одной строкой на каждом языке сайта (`{ "en": …, "ru": … }`) и необязательные `repo` и `website`, только с `https`.

Перед этим запустите в клоне `pnpm install` и `make check-web`: он собирает сайт и ловит битую карточку или запись.

## Если что-то не работает

- Журнал не пишется. Проверьте, что `.cyberzavod/bin/cyberzavod.mjs` на месте и `node` есть в `PATH` той оболочки, где запущен Claude Code. Если файла нет, его вернёт `npx cyberzavod sync`.
- Хуки подключили посреди сессии. В журнале нет начала сессии, поэтому у записи пусты проект, версия harness и процесс. Их можно заполнить на шаге редактуры, но проще начать новую сессию.
- Хук остановки не отпускает. Значит, красные проверки: исправьте то, что они печатают. При битом `.cyberzavod/project.json` или без `git` хук отпускает агента с сообщением и ничего не проверяет.
- `sync` отказывает. На месте сгенерированного файла лежит ваш: перенесите правила в `AGENTS.md` и запустите `sync --force`.

## Живой пример

Personal Finance Lab — внешний проект, который ведёт завод: [страница проекта](/projects/personal-finance-lab/). Запись [«Personal Finance Lab: финансовая лаборатория с нуля»](/recordings/2026-10-05-4365c610-2/) — вторая задача своей сессии. Первая задача той же сессии — запись `2026-10-05-4365c610` проекта `cyberzavod`. Так выглядят несколько задач в одной сессии.

Исходники harness, CLI и адаптера Claude Code лежат в репозитории завода: [`harness/`](https://github.com/bysavelii/cyberzavod/tree/main/harness), [`packages/cli`](https://github.com/bysavelii/cyberzavod/tree/main/packages/cli) и [`adapters/claude`](https://github.com/bysavelii/cyberzavod/tree/main/adapters/claude). В npm они выходят одним пакетом `cyberzavod`.
