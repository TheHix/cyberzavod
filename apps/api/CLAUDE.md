# API (apps/api)

Go, Postgres через pgx, миграции goose. Один бинарник с подкомандами `serve`, `migrate`, `healthcheck` (`cmd/api`). Все маршруты под `/api`: nginx отдаёт этот префикс в Go, остальное — статика сайта.

## Устройство

- `cmd/api` — только запуск: чтение конфига, сборка зависимостей, сигналы. Логики здесь нет.
- `internal/<пакет>` — пакет по ответственности (`httpapi`, `db`, `config`), а не по типу файла.
- `migrations/` — SQL-миграции, вшиты в бинарник.

## Правила

- Хендлеры и сервисы зависят от интерфейсов (`Pinger` и т. п.), объявленных там, где они используются, а не от `pgxpool` напрямую — чтобы тестироваться без базы.
- Изменение схемы — только новой миграцией `NNNNN_описание.sql` с секциями `-- +goose Up` и `-- +goose Down`. Применённые миграции не редактировать.
- Логи — `slog` в JSON с полями, а не склейкой строк. Конфигурация — только из переменных окружения через `internal/config`.
- Каждый запрос к базе и внешнему сервису — с контекстом и таймаутом.
- `gofmt` и `go vet` без замечаний.
