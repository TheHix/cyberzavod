# Сайт (apps/web)

Astro + SolidJS + Nano Stores, слои Feature-Sliced Design. Страницы собираются в статический HTML; JS получают только островки с `client:*`. Цех рисуется на canvas через PixiJS, интерфейс над ним — HTML и Solid.

## Слои FSD

- Слои в `src`: `app` → `pages` → `widgets` → `features` → `entities` → `shared`. Импорт только из слоёв ниже своего.
- `src/pages` — маршруты Astro, они же слой pages: только компоновка виджетов, без логики. Все страницы лежат в `src/pages/[...lang]/` (см. «Языки»). Единственное исключение из направления импортов: страницы подключают layout из `app/layouts`, потому что маршрутизация в Astro живёт в `pages`.
- `features/journal-sync` — связь журнала сборки с цехом: модульный стор `$sceneSpeech` (до какой речи дошёл цех), `connectScene` (цех подключает сюда свою модель) и `seekScene` (журнал просит перемотку). Журнал и цех — разные виджеты и друг друга не импортируют.
- Слайс наружу отдаёт только то, что есть в его `index.ts`; глубокие импорты в чужой слайс запрещены.
- Логика, которую можно написать без браузера, идёт в `packages/core` или `shared/lib` и покрывается тестом.

## Записи

- Опубликованные записи лежат в `recordings/published/` в корне репозитория и подключаются через алиас `@recordings` (`astro.config.ts`). Читает их только `entities/recording`: каждая проходит `parseRecording`, битая запись роняет сборку.
- Страница записи — `/recordings/<id>/` и `/ru/recordings/<id>/`, адрес собирает `recordingUrl(id, locale)`. Запись не переводится: язык страницы меняет интерфейс вокруг неё, а не тексты записи.
- Журнал сборки (`widgets/build-journal`) получает полную запись: промпты, вмешательства и реплики одним списком по времени, у вмешательства и реплики — полный текст. Остров с цехом получает `briefOf(recording)` — без полных текстов реплик и вмешательств, чтобы они не попали в `props` острова и не раздули страницу; цеху нужна только строка над говорящим.
- Каждая запись журнала — остров `client:visible` (`JournalEntry`) со статичным телом в слоте: полные тексты идут слотом, а не в `props`. Пока панель закрыта, записи не видны, и JS журнала не грузится. Подсветка (`aria-current` у `Card`) и кнопка «показать в цехе» появляются только с JS; без него — прежняя разметка. «Показать в цехе» перематывает цех и закрывает журнал (`popovertargetaction="hide"`), чтобы сцена была видна на любой ширине. Номера промптов, вмешательств и реплик в журнале те же, что у `PromptCue.index`, `InterventionCue.index` и `MessageCue.index`. Вмешательство — запись с меткой «человек · <причина>» (`labelOf(intervention, locale)` из `entities/intervention`, причины — `INTERVENTION_LABELS` в `shared/config/interventions.ts`), строкой и полным текстом; якорь `intervention-<n>` собирает `interventionAnchor`, у реплики — `message-<n>`.

## Проекты

- Карточки проектов лежат в `projects/<id>.json` в корне репозитория и подключаются через алиас `@projects` (`astro.config.ts`). Читает их только `entities/project`: каждая проходит `parseProject`. Битая карточка и запись, чей `project` не имеет карточки (`UnknownProjectError`), роняют сборку.
- Страница проекта — `/projects/<id>/` и `/ru/projects/<id>/`, адрес собирает `projectUrl(id, locale)`. Это внешняя ссылка «Built at Cyberzavod» из чужих проектов: английский адрес в корне не менять.
- Раскладка страницы проекта — как главной: на поле цех с последней сборкой проекта и её журнал; карточка проекта (`widgets/project-card`) и список его сборок — в выезжающей панели «Проект», кнопка которой есть в меню только на этой странице. Панель сама не открывается.
- Остров цеха получает проект как `ProjectLink` (`projectLinkOf(project, locale)`: название и адрес на языке страницы) и импортирует из `@/entities/project` только тип: значение затянуло бы в клиентский чанк карточки с описаниями.

## Гайды

- Гайды лежат в `guides/<id>.md` в корне репозитория и подключаются через алиас `@guides` (`astro.config.ts`). Читает их только `entities/guide`: имя файла — id гайда (`guideIdOf`: строчные латинские буквы и цифры через дефис), frontmatter проходит `parseGuideMeta`: `title` и `description` — непустые строки в одну строку, `order` — целое число. Битый гайд роняет сборку; новый гайд — новый файл, без правок кода.
- Тело гайда начинается с `##`: заголовок `h1` рисует страница из `title`. Таблиц в гайдах нет, вместо них списки.
- Страница гайда — `/guides/<id>/` и `/ru/guides/<id>/`, адрес собирает `guideUrl(id, locale)`. Это текст в поле (`widgets/guide-article`: `Panel` с `scrollable`, внутри `Prose`), а не панель поверх цеха: страница не прокручивается, текст прокручивается в панели. Список гайдов — в выезжающей панели «Гайды» (`widgets/guide-list`), кнопка которой есть в меню везде.
- Подсветка синтаксиса в Markdown выключена (`markdown.syntaxHighlight: false`): Shiki красит код цветами своей темы инлайн-стилями, а цвета сайта берутся только из токенов.
- Кнопки «копировать» у блоков кода ставит остров `CopyCode` (`features/copy-code`, `client:idle`): после загрузки он оборачивает каждый `pre > code` статьи в `codeBlockClass()` и монтирует рядом `CopyButton`. Без JS кнопок нет, код читается как обычный блок.

## Языки

- Сайт на двух языках: английский в корне (`/`, `/recordings/<id>/`, `/projects/<id>/`, `/guides/<id>/`), русский под `/ru/`. Язык по умолчанию и список языков — `DEFAULT_LOCALE` и `LOCALES` в `shared/i18n/locale.ts`; встроенный `i18n` Astro не включён: список языков был бы вторым, рядом с `LOCALES`. Новый язык — член `LOCALES`, и компилятор укажет всё, что к нему не готово.
- Маршруты — `src/pages/[...lang]/…`. `getStaticPaths` каждой страницы строится как `LOCALES.flatMap(locale => …)`: `params.lang = localeParam(locale)` (у языка по умолчанию `undefined`, страница лежит в корне), язык приходит в страницу через `props.locale`. Страница собирается из одного файла на оба языка, и язык в ней не вычисляется из адреса. Адреса — `localizedPath(locale, path)` и `recordingUrl`/`projectUrl`/`guideUrl`/`projectLinkOf` с вторым параметром `locale`; `pathWithoutLocale(pathname)` снимает префикс (`GameLayout` берёт путь без языка из `Astro.url.pathname` и отдаёт его `BaseLayout` и `Sidebar`).
- Тексты интерфейса — в словаре `UI_TEXT` (`shared/i18n/ui-text.ts`, группы по месту на странице) и в таблицах `Translated<T>` рядом с данными (`STAGE_LABELS`, `FOREMAN_LABEL`, `INTERVENTION_LABELS`, `LOGO_LINES`, `LOGO_SHORT_LINES`, `site`). `Translated<T>` — `Record<Locale, T>`: без `en` или `ru` у любой записи `astro check` падает. Текст с параметрами — функция в каждом языке; число со словом — `PluralWords` и `formatCount(count, words, locale)`. Строки в компонентах не пишем: всё идёт из словаря, кроме ошибок для разработчика (`throw`, `console.error`) — они русские. Пустую строку и параметр, не дошедший до текста, ловит `ui-text.test.ts`: каждую функцию-лист он вызывает с пробой на каждый параметр (`probe-1`, `probe-2`, …) и проверяет, что все пробы есть в результате. Формы числа в этот тест не попадают, они не функции, а строки `PluralWords`: их выбирает `formatCount`, его проверяет `format.test.ts`.
- Числа, даты и длительность форматируются по языку страницы (`formatTokens`, `formatDate`, `formatDuration` с параметром `locale`, форматтеры `Intl` по `LOCALE_TAGS` через `byLocale`). `navigator.language` нигде не читается: страницы собираются заранее, и язык зрителя им неизвестен.
- Язык в острове — пропс `locale` корня острова (`Factory`, `JournalEntry`, `CopyCode`), дальше `LocaleProvider` и `useLocale()` из `shared/i18n/locale-context.ts`. Entities получают `locale` вторым параметром (`routeOf`, `labelOf`, `recipientOf`).
- Таблички станков и мастера в цехе и логотип в меню — на языке страницы: графика получает язык в `loadFactoryGraphics(locale)`, надписи логотипа — `LOGO_LINES` и `LOGO_SHORT_LINES` в `shared/config/logo.ts`.
- Что пока не переводится. Гайды и карточки проектов показываются в оригинале на английской странице тоже, их язык — `CONTENT_LOCALE`, он ставится атрибутом `lang` на статью гайда, на название и описание в списке гайдов и на описание в карточке проекта; ссылки на страницы сайта внутри гайда и карточки получают язык страницы (`localizeLinks`, `localizeHref`). Записи сборок не переводятся и не помечаются `lang` до #33.
- Переключатель языка — ссылка на ту же страницу на другом языке, с `hreflang`, `lang` и самоназванием языка (`LOCALE_NAMES`: данные языка, а не текст интерфейса, поэтому они лежат в `locale.ts`, а не в `UI_TEXT`). Доступное имя плитки начинается с видимой подписи («RU — Русский», `UI_TEXT.menu.language`): подпись входит в имя (WCAG 2.5.3), `title` — самоназвание. Она есть в панели «О заводе» первой строкой на всех раскладках и в меню на широком экране — в нижней строке рядом с «Код» (раскладка этой строки — в «Игровой экран»).
- SEO. `BaseLayout` ставит `<html lang>`, `canonical` на саму страницу и `hreflang` на каждый язык и `x-default` абсолютными адресами от `site`; карта сайта — `@astrojs/sitemap` с теми же `LOCALES`.
- Тест по сборке — `build-tests/` (`pnpm check` гоняет его после `astro build`: `vitest.build.config.ts`). `readBuiltSite(dist, origin)` читает `dist/`, функции `brokenLinks`, `missingAlternates`, `foreignLocaleLinks`, `pagesMissingFromSitemap` отдают список находок; `built-site.test.ts` проверяет их на маленьких сайтах, `dist.test.ts` — что на настоящем `dist/` находок нет. Новая страница или ссылка, которая уводит на чужой язык, ломает этот тест.

## Состояние: `model` и `ui`

- Состояние, завязанное на логику, — что проигрывается, где мы, что раскрыто, готова ли графика, — живёт в сегменте `model/` слайса на [Nano Stores](https://github.com/nanostores/nanostores): атомы, `computed` и действия-функции. Без Solid и DOM, с тестами на Vitest.
- Сторы называются с `$` (`$playback`, `$scene`). Наружу модель отдаёт их только для чтения (`ReadableAtom`); менять состояние можно лишь её действиями.
- `ui/` — представление: компоненты читают сторы через `useStoreValue` (`shared/lib/use-store-value.ts`) и вызывают действия. Своё состояние в компоненте — только чисто визуальное (наведение, фокус); всё, от чего зависит логика, — в модели.
- `useStore` из `@nanostores/solid` не использовать: он перекладывает значение в Solid-стор через `reconcile` и правит прежний объект на месте. Объекты кадра ядра общие со сценарием — такая правка портила сцену (рабочие места уезжали в проход). Сценарий ядра заморожен, так что правка на месте теперь падает сразу.
- Правила предметной области — в модели как `computed` (например, `$promptPosition`: над кем висит промпт — над мастером, который говорит его у станка; так же `$interventionPosition`), а не в компонентах. Компонент подписывается на узкий стор, который ему нужен, а не на всю сцену.
- Если экземпляров на странице может быть несколько, модель создаётся фабрикой (`createFactoryModel`) и раздаётся компонентам слайса через контекст Solid, а не пропсами. Общее между островками состояние — модульный стор в `model/`.
- Драйверы браузера (requestAnimationFrame, наблюдатели) — в `ui/`: они слушают сторы и вызывают действия модели, логики не содержат.
- Чистые вспомогательные расчёты слайса — в `lib/`, с тестами.

## Игровой экран

- Весь сайт — игровое поле: страница не прокручивается, цех нарисован на всё окно (`app/layouts/GameLayout.astro`). Слева меню (`widgets/sidebar`), справа HUD цеха, длинное содержимое — записи, журнал сборки, проект, гайды, «о заводе» — в выезжающих панелях поверх.
- Панели — нативный `popover` (`Drawer` из kit): открываются кнопкой с `popovertarget` без JavaScript, а их содержимое всегда есть в HTML страницы — его видят поисковики. id панелей — в `shared/config/panels.ts`.
- Узкий экран — `(width <= 48rem) and (height > 40rem)`: меню становится строкой сверху, HUD — карточкой снизу. Низкий — `height <= 40rem` (телефон боком; сюда же попадают ноутбуки с невысоким окном): меню остаётся слева и помещается целиком без прокрутки — плитки становятся строкой «иконка + подпись», логотип — короткая табличка «КЗ» («CZ» на английском); HUD лежит полосой под полем на всю ширину справа от меню: полка речи и управление в двух равных колонках. Узкий и низкий вместе — `(max-width: 48rem), (max-height: 40rem)`: так сжимаются kit и HUD, скрывается ярлык `Panel`, HUD уходит под поле, пузыри уступают полке речи, а заголовок сборки и скорость скрыты.
- Больше всего плиток в меню на странице проекта: цех, записи, журнал, проект, гайды, о заводе и ссылка на код. Чтобы они помещались на 360×740 строкой и на 740×360 без прокрутки, на узком экране поля меню меньше, плитки плоские, как вкладки (рамка и тень только у меню), подпись из двух слов переносится, а нижней строки («Код» и язык) нет — ссылка на код и переключатель языка остаются в панели «О заводе» (`Sidebar.module.css`, `Button.module.css`); на низком — отступы плиток и меню минимальные, плитки тоже плоские, а из нижней строки остаётся только «Код»: две плитки «иконка + подпись» в ряд не помещаются в ширину меню. На широком «Код» и язык — плитки `halfTile`, стоят в одной строке пополам (виджет задаёт им только `flex`), поэтому переключатель не прибавляет меню высоты; новую плитку в эту строку не добавлять, а отдельную ставить выше с проверкой высоты. Новая плитка меню — снова проверить оба размера на странице проекта. Английские подписи («Floor», «Builds», «Log», «Project», «Guides», «About») нарочно короткие: длинное слово сначала укорачивают в словаре, а не правят CSS.
- Пороги `48rem` (узкий) и `40rem` (низкий) повторяются в медиазапросах tokens.css, Button, Drawer, Panel, Sidebar, Hud, PlaybackControls, Factory и GameLayout — переменные CSS в условиях медиазапросов не работают. Менять их — только вместе во всех этих местах.
- Меню и HUD лежат над пузырями речи (`z-index: 3` против 2 у `.overlay`): пузырь не закрывает их и не перехватывает нажатия.
- На узком и низком экране пузыри скрыты, а речь показывает полка `SpeechDock` в HUD (на узком — над управлением, на низком — рядом с ним): метка маршрута, «подробнее» и две строки текста постоянной высоты (`Title lines={2}`, строка метки — `--chip-height` из токенов), чтобы поле не прыгало; пока никто не говорит, на ней название сборки. Заголовок сборки на узком и низком экране остаётся в разметке скрытым — это `h1` страницы записи; строка скорости там же скрыта.

## UI-kit (`shared/ui`)

- Внешний вид — только отсюда. Токены (`tokens.css`) — единственный источник краски, контура, «приподнятых» теней, скруглений, шрифтов, шкал кегля и отступов, движения и размеров раскладки; графика цеха читает краски оттуда же. Стиль — яркий тайкун: толстый тёмный контур и жёсткая тень вниз.
- Компоненты: `Button` и `ButtonLink` (вид `primary`/`secondary`/`ghost`/`link`, размер, раскладка `text`/`icon`/`round`/`tile`/`halfTile` — плитка на половину строки меню со своим кеглем и без боковых полей, две такие стоят в ряд, на узком и низком экране она обычная плитка; `buttonClass()` — тот же вид для элементов, которые не могут быть кнопкой, например внутри `<summary>`), `Panel` (`scrollable` — содержимое прокручивается внутри панели), `Prose` (текст статьи из готовой разметки, например Markdown; `codeBlockClass()` — обёртка блока кода с местом под кнопку), `CopyButton` (кнопка «копировать» с итогом на пару секунд; текст читается в момент нажатия; подписи по состояниям — пропс `labels`), `Card` (`current` — текущая карточка списка, `aria-current`), `PixelPlaque` (табличка пиксельным шрифтом табличек цеха в SVG — логотип в меню; глифы и рисунок таблички — `shared/lib/pixel-plaque.ts`, их же берёт графика цеха), `Chip`, `Title` (`lines` — блок постоянной высоты на столько строк, лишнее обрезается), `BulletList`, `StatList`, `Slider`, `SegmentedControl`, `Drawer`.
- Kit не знает словаря: тексты, которые он показывает сам (подпись кнопки закрытия `Drawer.closeLabel`, подписи `CopyButton.labels`), приходят пропсами от того, кто его использует.
- Интерактивное (кнопки, слайдер, переключатели) построено на [Kobalte](https://kobalte.dev) — headless-библиотеке для Solid: клавиатура, ARIA и состояния от неё, вид наш. Новый интерактивный компонент — сначала смотреть, есть ли он в Kobalte.
- Виджеты собираются из компонентов kit и не повторяют их стили: если нужна новая кнопка, плашка, метка или поведение компонента на узком экране — это новый вид компонента в kit, а не CSS в виджете, и виджет не лезет во внутреннюю разметку kit. В CSS виджета — только раскладка (сетка, отступы) и то, что есть только у него.
- Цвета, отступы, кегль и движение — через токены. Собственные размеры компонента (ползунок, значок, расстояние пузыря) — именованные переменные в начале его класса (`--thumb-size: 1.6rem`), а не числа посреди правил.
- Движение (подъём кнопок, выезд панелей) — через токены `--motion-*` и `--*-shift`: при `prefers-reduced-motion` они обнуляются. Подъём при наведении — только под `@media (hover: hover)`.
- В `.astro` класс, переданный в Solid-компонент kit, не получает область видимости Astro и scoped-стиль к нему не применится — оборачивать содержимое в свой элемент.
- Пропсы вида не называть как атрибуты HTML: у `<a>` есть `shape`, у `<button>` — `form`; пересечение ломает типы.
- Иконки — `lucide-solid`, по одной: `import Play from "lucide-solid/icons/play"`.

## Цех (`widgets/factory`)

- `model/` — `playback.ts` (правила проигрывания, чистые функции) и `factory.ts` (модель цеха на Nano Stores: `$script` (сценарий на текущем плане), `$layout` (план из `FACTORY_LAYOUTS`; у сценария своя копия плана, поэтому план сравнивается по `$layout`), `$playback` — три производных от одного внутреннего атома, чтобы смена плана была одним изменением и подписчики не видели новый сценарий со старым моментом, `$scene`, `$recordingTime`, `$prompt`, `$promptPosition`, `$intervention` (вмешательство, которое сейчас говорит мастер у станции, где стоит работа) и `$interventionPosition` (над мастером), `$message`, `$messagePosition`, `$speech` — последний начавшийся промпт, вмешательство или реплика для подсветки в журнале, итоги `summary` (время, токены, промпты, возвраты, вмешательства), действия, в том числе `seekToSpeech` — перемотка к началу пузыря речи (промпта, вмешательства или реплики) без смены «идёт или пауза» — и `setLayout`: сценарий строится заново на другом плане, а момент записи, «идёт или пауза» и скорость сохраняются через `carryTime`). `Factory.tsx` выбирает план по форме поля и экрана (`layoutFor`, экран — размер холста на всё окно) при монтировании и при каждом замере; у поля без площади план остаётся прежним. `lib/speech-timeline.ts` — промпты, вмешательства и реплики сценария одним списком по началу (`speechTimeline`, `speechAt`, `speechStart`).
- `graphics/` — как цех нарисован. Модель и компоненты знают только интерфейс `FactoryGraphics` (`mount`, `setLayout(layout)`, `render(scene)`, `resize(width, height, frame)`, `toScreen`, `destroy`): пол — на весь холст, план — вписан в поле `frame` между меню и HUD; `setLayout` заменяет неподвижный план (пол, станки, кабинет), а вписывает его следующий `resize`; рабочие, мастер и деталь остаются. Новая графика (спрайты, 3D) — новая реализация, которую возвращает `loadFactoryGraphics(locale)`; остальное не меняется. PixiJS импортируется только здесь и только динамически — отдельным чанком.
- Pixi подключается без `Application` и автозагрузки расширений (`manageImports: false`): WebGPU, события, accessibility, DOM и фильтры Pixi в чанк не попадают. Нужное расширение подключается явным импортом `pixi.js/<модуль>` в графике.
- `graphics/pixel/` — цех в пиксель-арте. Рисунки — массивы строк в коде, буква — краска (`art.ts`: `ART_LEGEND`, `paintArt`); при встраивании (`mount` и `setLayout`) они красятся токенами из `palette.ts` (своих красок в коде нет: белый и каска мастера — тоже токены из блока графики цеха, тени и блики — ступени `shade()`) и запекаются в текстуры (`textures.ts`: `CanvasSource` с `scaleMode: "nearest"`, единственное место с DOM-холстом). PNG-атласа нет: ни загрузчика, ни лишнего запроса. Клетка — 16 пикселей рисунка на единицу плана (`units.ts`), множитель экрана целый в пикселях устройства (`fitPixelPlan` в `bounds.ts`, рендерер без сглаживания, `resolution` равен `devicePixelRatio` без потолка, у холста `image-rendering: pixelated`). Спрайты не поворачиваются: `heading` квантуется в 4 стороны (`frames.ts`: вниз, вверх, вбок; влево — зеркало), объекты сортируются по `y`. Поза человека и такт станка тоже выводятся из кадра сцены в `frames.ts`: шаг, шаг с деталью (`carryA`/`carryB`), руки вперёд при передаче (`reach`), удар у станка (`workA`/`workB`, `WORK_FRAME_MS`), жест мастера, пока он говорит (`talkA`/`talkB`, `TALK_FRAME_MS`); слушающий мастер стоит. `machineWorkOf` даёт станку тот же такт, что рабочему, и покой, когда рабочий не бьёт; новая поза — строка в `ACTOR_ART` (по рисунку на каждую сторону) и в `ACTOR_POSE_IN_PLACE`. Остальное: `floor.ts` (плитка до краёв, проход прямоугольниками — только по горизонтали и вертикали, `lane.ts` бросает ошибку на диагональ; площадки), `machines.ts` (станок — рисунок на этап в таблице `MACHINE_ART`, лампа отдельными спрайтами; работа станка — накладка на каждый такт `WorkBeat` в таблице `MACHINE_WORK_ART`, в ней только пиксели, которые отличаются от корпуса, — это проверяет тест; накладки лежат поверх корпуса и под лампой, `showMachineWork` меняет только их видимость; новый такт в `machines.ts` — только рисунок в `MACHINE_WORK_ART`), `office.ts` (стол кабинета), `plaques.ts` и `glyphs.ts` (таблички пиксельным шрифтом: глифы строками и рисунок таблички — в `shared/lib/pixel-plaque.ts`, только заглавная кириллица и латиница из названий этапов, мастера и логотипа; место таблички считают и рисование, и `planBounds`), `actor-art.ts` (рисунки человека 16×16: все стороны и позы, полными фигурами), `actors.ts` (рабочие, мастер, деталь; деталь в руках лежит над несущим, когда тот смотрит вниз, и под ним, когда вверх или вбок, чтобы руки были поверх ящика: слой выводит `crateLayerOf` из кадра по таблице `CARRIED_IN_FRONT` и отстоит от слоя несущего на полпикселя, чтобы не встать между ним и соседом; мастер — тот же человек своего цвета и в белой каске; кадры всех поз запекаются заранее по `ACTOR_ART`, и `destroy` освобождает их все, а не только висящие на спрайтах; `ACTOR_FIGURE`, по которой таблички обходят людей, считается по всем сторонам и позам на месте, с поднятыми руками), `renderer.ts` (выбор рендерера: WebGL, без него Canvas). Новый этап или новая буква на табличке — новая строка в таблице.
- Названия этапов и мастера (`STAGE_LABELS`, `FOREMAN_LABEL`, оба `Translated`) — в `shared/config/stages.ts`: их берут и таблички станков на языке страницы, и маршруты реплик (`entities/message`: «Код → Проверки» и «Code → Tests», «Постановка → мастер» и «Spec → foreman»). В коде мастер — `foreman`.
- `ui/` — `Factory.tsx` собирает модель, графику и часы, подключает модель к журналу (`connectScene`) и меряет поле; `Hud` (счётчики сборки: время, токены, промпты, возвраты, вмешательства), `SpeechDock`, `PromptBubble`, `InterventionBubble`, `MessageBubble`, `PlaybackControls` только отображают (рамку, расположение и хвостик пузыря к говорящему даёт общий `SpeechBubble`; «подробнее» у реплики и вмешательства ставит паузу и открывает журнал на них через `open-journal.ts`: `showMessageDetails`, `showInterventionDetails`); `frame-clock.ts` двигает модель по кадрам, пока сцена идёт, цех виден и вкладка открыта. При `prefers-reduced-motion` сцена стартует на паузе.
- Кадр рисуется по подписке на `$scene`: идёт сцена — каждый кадр, стоит — только после перемотки и смены размера. В кадре не создаются объекты: у готовых спрайтов меняются текстура кадра, место, зеркало, видимость и `tint`; рисунки запекаются в текстуры при встраивании.
- Текст (промпты, вмешательства и реплики над говорящими) — HTML поверх холста: он чёткий, доступен и раскрывается по клику.

## Компоненты

- Интерфейс — Solid (`.tsx`), статичная разметка — `.astro`. Директиву `client:*` ставить только там, где нужна интерактивность. Solid-компонент без `client:*` рендерится в статический HTML — так kit используется и в `.astro`.
- В Solid компонент выполняется один раз: производные значения — функции или `createMemo`, а не переменные; пропсы не деструктурировать, иначе теряется реактивность.
- Стили — CSS-модули рядом с Solid-компонентом, `<style>` внутри `.astro` (Astro ограничивает его компонентом); значения — токены kit.

## Импорты

- Между слоями и слайсами — через `@/…`, внутри слайса — относительные.
- Публичный API слайса подключается по папке (`@/widgets/factory`, `@/shared/ui`), отдельные файлы — с расширением `.ts`/`.tsx`.
